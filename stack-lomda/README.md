# לומדת תרגול STACK → SCORM (POC)

ניסוי: להמיר שאלות STACK מ-Moodle ללומדת SCORM שרצה **כולה בצד הלקוח** (בדפדפן),
כדי לעקוף את האיטיות של STACK בשרת. התיקייה עצמאית — קל להעביר לריפו נפרד אם זה עובד,
או למחוק אם לא.

## למה זה לא "ייצוא" רגיל

ייצוא ה-XHTML של Moodle מכיל רק את **טקסט השאלה**. הוא כותב במפורש
`export of stack type is not supported` — כלומר הלוגיקה של STACK (הגרלת המשתנים
ובדיקת התשובות שרצה על מנוע Maxima בשרת) **לא** מיוצאת. לכן בלומדה אנחנו
**מממשים מחדש** ב-JavaScript את שני החלקים האלה:

- **הגרלה** (`generate`) — במקום המשתנים האקראיים של STACK.
- **בדיקת תשובה** (`parse.js`) — במקום ה-answer tests. הבדיקה נומרית עם סובלנות,
  כך שתשובות שקולות מתקבלות: `1/2` = `0.5`, `sqrt(8)` = `2*sqrt(2)`, `(3,5)` = `3,5`.

## מבנה

```
stack-lomda/
├── index.html              נקודת הכניסה
├── imsmanifest.xml         מניפסט SCORM 1.2 (מה ש-Moodle קורא)
├── build.sh                אורז ל-dist/stack-lomda-scorm.zip
├── README.md
└── assets/
    ├── css/style.css
    └── js/
        ├── scorm.js        דיבור עם Moodle (מעקב/ציון). no-op בלי LMS.
        ├── parse.js        פרסור והשוואת תשובות (מחליף answer tests)
        ├── questions.js    הגדרות השאלות (הגרלה + תשובות + פתרונות)
        └── app.js          הבקר (בונה כרטיסים, בדיקה, פתרון, ציון)
```

## השאלות שכלולות (מתוך הייצוא)

1. חיבור וקטורים וכפל בסקלר ב-\(\mathbb{R}^2\) — מקור 9087352
2. מכפלה סקלרית, נורמה, זווית והטלה ב-\(\mathbb{R}^3\) — מקור 9087357
3. מכפלה וקטורית ושטח משולש — מקור 9087807

## בדיקה מקומית

פותחים את `index.html` בדפדפן. הכל עובד חוץ ממעקב ה-SCORM (שנכנס לפעולה רק בתוך
Moodle). דרושה גישה לאינטרנט בשביל MathJax ו-math.js (נטענים מ-CDN).

## אריזה והעלאה ל-Moodle

```bash
./build.sh          # יוצר dist/stack-lomda-scorm.zip
```

ב-Moodle: הוספת פעילות → **חבילת SCORM** → העלאת ה-zip → שמירה.

## הוספת שאלות

מוסיפים אובייקט חדש למערך ב-`assets/js/questions.js` באותו מבנה
(`generate`, `text`, `inputs`, `answers`, `solution`). אין צורך לגעת בשאר הקבצים.

## מגבלות ידועות (POC)

- **בדיקה נומרית בלבד** — לא בדיקה סימבולית מלאה כמו STACK. לשאלות עם תשובה מספרית/וקטורית
  זה מספיק ומדויק; לתשובות סימבוליות פתוחות (פולינום כללי וכו') יידרש מנוע חזק יותר.
- **MathJax ו-math.js מ-CDN** — לפריסה עצמאית לגמרי (אופליין) כדאי להוריד אותם לתוך `assets/`.
- הפתרונות וההגרלות נכתבו ידנית לפי טקסט הייצוא — כדאי לוודא שהם תואמים למקור ב-STACK.
